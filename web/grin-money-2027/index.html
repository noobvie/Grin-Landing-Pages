Grin: private cash, with nothing on the chain to read.

Grin is a privacy-focused cryptocurrency using the Mimblewimble protocol. It was described by an anonymous author, started by a pseudonymous developer, and is kept running by ordinary people. This file explains it from the start, no background needed.

What you hold is your own business. Grin records no amounts and no addresses on its chain, so there is no balance for anyone to read: not , not . Exchanges and hosted wallets you use still see what passes through them.

Exhibit A · The protocolPage 2 of 13

What is Mimblewimble?

Mimblewimble is a way to build a blockchain that hides amounts, writes no addresses, and throws away spent coins. Grin is a minimal implementation of it.

Origin
Paper by the pseudonymous “Tom Elvis Jedusor” (Voldemort’s name in the French Harry Potter books), dated 19 July 2016. It was posted anonymously to the #bitcoin-wizards IRC channel as a text file on a Tor (.onion) server on 2 Aug 2016 (UTC; 1 Aug in US time zones).
Paper
MimbleWimble Origin (2016)
Follow-up
Andrew Poelstra published a follow-up paper with refinements in October 2016.
Grin
Ignotus Peverell announced Grin, a minimal implementation, on 20 Oct 2016; mainnet followed on 15 Jan 2019. Igno stepped away a few months after launch (last commit April 2019).
Status
Active. Mainnet since 15 January 2019. Open source since 2016.

Core properties

  • No addresses on chain. Sender and receiver build each transaction together by passing a “slatepack” (a block of text) by copy-paste, file, QR, or automatically over Tor. Wallets also give you a slatepack address you can share, but it is never written to the chain: it only encrypts and routes that exchange.
  • Hidden amounts: each amount is locked inside a cryptographic commitment (Confidential Transactions, using Pedersen commitments, plus Bulletproof range proofs that show no amount is negative).
  • Cut-through drops spent outputs, so the chain keeps only unspent outputs, block headers and a small kernel per transaction (a tiny signature proving the transaction is valid).
  • No scripting language: a small, fixed set of transaction kinds.
  • Linear emission: 60 GRIN per minute, forever.

No company

No company, no foundation, no pre-mine. Development is funded by donations.

A-2 · Privacy

Private by default

No amounts and no addresses on chain. Transactions in a block merge together, which makes them harder to link, but an observer running many nodes can still link many of them. Grin reduces linkability; it does not remove it.

A-3 · Size

A small chain

Cut-through keeps the chain small: a pruned node needs only a few gigabytes.

A-4 · Launch

Fair launch

No ICO, no airdrop, no venture backing. 60 GRIN per minute, the same forever.

Exhibit B · ProcedurePage 3 of 13

How Grin works, in four steps

A Grin payment is a short conversation between two wallets, then a block that hides what it can and forgets what it no longer needs.

  1. Build it together

    Sender and receiver build each transaction interactively. No address is ever written on chain: the wallets exchange a “slate” (as text, a slatepack) to build a joint signature. A slatepack address, if you use one, only routes and encrypts that exchange.

  2. Hide the amount

    Amounts are hidden using Confidential Transactions (Pedersen commitments). Only sender and receiver know the value transferred.

  3. Relay and merge

    A new transaction is first passed through a few peers (a Dandelion++ variant) to make it harder to tell where it came from. In a block, transactions are merged by CoinJoin-style aggregation (many transactions combined into one), which makes individual transactions harder to trace.

  4. Cut through

    Spent outputs are cut through. What is left is the unspent outputs, the block headers, and one small kernel per transaction, so the chain grows far more slowly than the transaction history.

Exhibit C · FindingsPage 4 of 13

How Grin compares: nine findings

  1. Time-backed monetary policy

    60 GRIN are minted on average every 60 seconds, forever. No halving shock, no supply cliff: every block pays the same 60 GRIN in 2019 and in 2099. One minute of network time equals 60 new coins, so the supply is as predictable as a clock.

  2. Privacy on chain, honestly stated

    No addresses and no amounts are ever written to the blockchain. Which outputs were spent together can often be worked out by someone watching the network with many nodes. Grin reduces this linkability; it does not remove it.

  3. Compared with gold: checkable in digital form

    Nobody can audit the world’s gold supply, and tokenized gold depends on trusting a custodian. Grin’s supply is mathematically verifiable by anyone running a full node: every node checks that the hidden amounts add up to the known emission. No custodian required.

  4. Compared with USD-pegged coins: no decree

    Fiat-backed stablecoins import their central bank’s monetary policy. Grin’s emission is fixed in the consensus rules. Changing it would take a hard fork (a rule change every node must upgrade to) that node operators would have to choose to run, and there is no company or foundation to decree one.

  5. Compared with Bitcoin: a reward that keeps paying

    Bitcoin’s 21 million cap means that once the last coin is mined, miners rely entirely on transaction fees. Whether that keeps the network secure is an open economic question. Grin’s constant block reward keeps paying miners.

  6. A small footprint

    Since 2019 the chain has stayed compact: spent outputs are cut through, so a pruned node stays small.

  7. Emission for generations

    With a fixed reward and a growing supply, the inflation rate approaches zero over time, with no hard stops or abrupt halvings. Annual inflation is about 13% in late 2026 and falls every year. No coins were set aside for insiders.

  8. Simple and open source

    A deliberately minimal protocol. No proprietary components, no hidden supply curves, no pre-allocated coins. Open source since 2016.

  9. Time cannot be copied (our opinion)

    We think this is what makes Grin hard to replicate: anyone can fork the code, but a fork resets the clock. The proof-of-work mined since 2019 cannot be mined again.

E-1 · Wallet

Grim

Cross-platform wallet app with a built-in node, written in Rust. Android, Linux, macOS, Windows (iOS announced, not out yet as of Nov 2026). Actively developed (v0.3.6, Aug 2026).

  • wallet
  • recommended

E-2 · Mobile payments

Goblin

A mobile-first payments app built on Grim. Pay a username like alice@goblin.st, or a Nostr key. No sign-up: your identity is a Nostr key kept on your device, separate from your wallet seed.

Payments travel as sealed, encrypted messages over Tor built into the app; relays never see the amount. Android, Linux, macOS, Windows (iOS coming, as of Nov 2026).

  • tor

One Bash toolkit for a Linux server: full node, pruned node, explorer, public API, mining pool, wallet portal, Nostr relay, all semi-automated. A dozen live demo sites are built with it.
